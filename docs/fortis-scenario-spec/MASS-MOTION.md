# Массовое учебное движение: кинематика и Монте-Карло

Версия 3 · 2026-10-21. Пользователь утвердил подход «кинематика + Монте-Карло + явные правила» и запросил начало реализации. Этот документ расширяет SCN-01. Бригады, ремонт, обслуживание и decision AI исключены из ближайшего этапа.

## Результат первой версии

В существующей сцене Factory доступны массовые прогоны длительностью от 30 до 90 минут с шагом 1 минута. Различаются общее количество объектов за сценарий и одновременно активные объекты. Интерфейс предлагает ползунок от 100 до 500 объектов с шагом 1; расчётный потолок первой версии — 1000. Это границы первой реализации, не гарантия производительности на любом устройстве.

По замечанию пользователя ограничение тремя дорожками исключено из массового режима. Каждый объект получает собственный непрерывный угол входа из полного круга 0–360°. Равномерное распределение — начальное учебное допущение, не эмпирическая модель. Исходные три записи сохраняются только в отдельном контрольном просмотре. Геометрия предприятия и ландшафт не меняются. Исходы воздействия, обнаружение, перехват, оптимизация маршрутов и физика полёта не вычисляются.

## Пространственная модель mass-motion@3

По уточнению пользователя точки движутся в сторону предприятия, а на входе в зону показывается условное срабатывание по учебному правилу. Для каждого объекта θ=360W, W∈[0,1). Угол отсчитывается от севера по часовой стрелке. Старт: x=10000·sin(θ), y=10000·cos(θ). Конец: x=R·sin(θ), y=R·cos(θ), где R=320 м — учебная граница вокруг всей площадки, равная factoryCampusSize и охватывающая четыре участка. Между ними линейная интерполяция по локальному прогрессу движения. Высота полёта исключена: z=0 обозначает схему в плане. В 3D маркеры проецируются на отображаемый рельеф с визуальным отступом 8 м; линия границы поднята на 3 м. Эти отступы нужны для читаемости, не являются высотами полёта. Геометрия зданий, масштаб площадки и ландшафт сохранены.

Правило `training-boundary@1`: при первом достижении границы в момент b движение заканчивается и фиксируется ровно одно «Учебное срабатывание» с ID объекта, временем и сектором входа. Учебное срабатывание задано для каждого достижения границы; это не вероятность успешной защиты и не расчёт эффективности средств. R не связан с ТТХ или размещениями из DefenseProject. Оценки поражения, перехвата и наведения на здания не добавлены.

Угол непрерывный: разрешены любые направления, без привязки к 3 или 8 маршрутам. Восемь секторов по 45° используются только для статистики. Сектор С: [337,5°,360°)∪[0°,22,5°), далее СВ/В/ЮВ/Ю/ЮЗ/З/СЗ. В каждом прогоне сохраняются число появлений и точный пик одновременной активности по каждому сектору. Из пакета выводится p90 пиков для каждого сектора; эти значения не складываются в общий пик, поскольку пики могут приходиться на разные моменты.

## Временная модель

Вход: версия модели, точные версии сцены/terrain/enterprise, длительность H, количество N, seed (uint32), относительный разброс s (в UI галочка «Неравномерно по времени»: выключена s=0, включена s=0,25; внутренний валидатор поддерживает 0…0,5), индекс прогона. Пространственная модель — материальная точка. Направления выбираются для каждого объекта и меняются между индексами прогонов.

Для каждого объекта i с исходной длительностью D=240000 мс берутся независимые псевдослучайные U,V из [0,1). Длительность d=D·(1+s·(2U−1)). Нормированное положение в расписании q=i/(N−1), при N=1 q=0. Время появления a=((1−s)·q+s·V)·(H−d). Время завершения b=a+d. Формула обеспечивает 0≤a≤b≤H без обрезки результатов. Распределение времени появления условно зависит от d; его нельзя описывать как независимое от длительности. При s=0 расписания идентичны, но углы входа между прогонами продолжают меняться.

Состояния: ожидает при t<a; активен при a≤t<b; учебное срабатывание произошло при t≥b. Внутренний счётчик finished теперь отображается как «Учебные срабатывания»; ожидают+активны+срабатывания=N. При t=H все объекты достигли учебной границы. События выводятся из текущего времени и расписания, а не накапливаются обработчиком кадров: перемотка не создаёт дублей и не теряет событий. Зелёные отметки видны 60 секунд времени сценария после b, затем исчезают; счётчик и история сохраняются. В журнале показаны последние пять событий, отсортированные по времени убывания и ID при совпадении времени.

Прогресс движения p=(t−a)/d. Координаты вычисляются линейной интерполяцией между индивидуальными началом и концом. Перемотка вычисляет состояние непосредственно, без проигрывания предшествующих кадров. Единые монотонные часы, пауза, возврат к началу, ускорение 1/10/30/60×. Уход страницы в фон ставит паузу. Потеря WebGL сохраняет время и открывает доступный 2D.

Генератор — Mulberry32; производный seed = (seed + index × 0x9e3779b9) mod 2^32. Для времени объекта сначала выбирается U, затем V из основного потока. Для направлений используется отдельный Mulberry32 с seed runSeed XOR 0xa511e9b3; один W на объект. Изменение временного разброса не меняет направления того же seed/индекса. Seed, индекс прогона и версия генератора однозначно определяют расписание. Разные индексы используют производные seed; пакетный расчёт и открытие конкретного прогона используют одну функцию. Повторный запуск не использует Math.random или текущее время как источник случайности.

## Монте-Карло

Пакет содержит 100 либо 500 прогонов одного набора параметров. Каждый прогон возвращает точный пик одновременно активных объектов и среднее число активных за H. Пик вычисляется проходом по отсортированным событиям; при одинаковом времени завершения учитываются раньше появлений. Среднее равно сумме длительностей / H. График выбранного прогона строится по полной последовательности изменений счётчика, а не по редкой сетке времени.

Сводка: минимум, медиана, p90 и максимум общих пиков; среднее средних; p90 пиков по восьми секторам. Квантили определены методом ближайшего ранга ceil(p·R)−1. p90 — квантиль результатов, не доверительный интервал и не вероятность воздействия. Для каждого результата сохраняются индекс/seed. Нельзя называть эти числа оценкой реальной обстановки без калибровки исходных допущений.

Пакет считается без 3D, небольшими порциями с передачей управления браузеру. Есть прогресс и отмена. Отмена/смена параметров/выход не оставляют результат старого набора как актуальный. Частичный пакет не выдаётся за полный. При недостаточной отзывчивости по измерениям расчёт переносится в Worker; новая серверная подсистема пока не нужна.

## Интерфейс и рендер

Вход «Массовый прогон» в существующем модуле. Длительность и количество задаются ползунками с текущим значением и границами, доступны с клавиатуры. Галочка «Неравномерно по времени» включена по умолчанию; при выключении появления равномерно распределены по доступному интервалу и длительность движения фиксирована. При включении используется прежний учебный разброс появления и длительности 25%. Процент в UI не редактируется. Изменение любого из этих параметров сбрасывает выбранный прогон/время и инвалидирует пакет. Исходные учебные записи остаются доступны как контрольный пример. Настройки и результаты находятся вне карты. На карте — один выбранный прогон, активные маркеры с индивидуальными короткими следами движения; 3D использует InstancedMesh для маркеров и один LineSegments для следов, без DOM-подписи на каждый объект. Цвет обозначает сектор входа. Слой «Следы движения» скрывает только следы, не объекты. В 2D используются лёгкие маркеры. Счётчики «ожидают / активны / учебные срабатывания» согласованы с теми же временными границами.

Вход в массовый режим показывает общий обзор 360°. По уточнению пользователя отдельные кнопки «Обзор 360°» и «Предприятие и защита» над сценой удалены. Центральный маркер площадки открывает рабочий масштаб (zoom 24), включающий зелёный контур зоны; кнопка вписывания на карте возвращает общий обзор. Контур и события видны независимо от переключателей слоёв предприятия, рельефа и следов. «К следующему срабатыванию» ставит просмотр на паузу в точном времени следующего события и центрирует площадку; после последнего события кнопка недоступна. Запись журнала открывает соответствующее время и тот же вид. В обоих видах остаётся одинаковое количество активных объектов; зелёные отметки событий в активных не учитываются. Крупный план поясняет, что дальние объекты вне кадра. Центральный маркер площадки не зависит от видимости предприятия.

Камера и слои не меняют расчётное время. 30–90 минут — длительность сценария, а не обязательная длительность ожидания пользователя. Покадровая история не хранится. Нет новых backend routes, бизнес-записей DefenseProject, AI-вызовов, платных генераций или новых зависимостей. Выход из массового режима и перезагрузка сбрасывают локальную сессию.

## Проверка и приёмка первой версии

1. Повторяемость одинаковых входов и seed; различие разных индексов; нулевой временной разброс даёт одинаковые расписания при разных направлениях.
2. Валидация NaN/Infinity, диапазонов, целых N/seed/индекса и совместимости сцены; массовый генератор не зависит от контрольных записей.
3. Граничные времена появления/срабатывания; ожидают+активны+срабатывания=N; все достигли учебной границы при H; совпадение с интерполяцией индивидуального отрезка.
4. Точный пик и среднее на вручную вычисляемом примере, включая совпадающие события; проверки квантилей и секторных пиков.
5. Перемотка и часы до 90 минут; переключение 2D/3D не меняет выбранный прогон и время.
6. Полный пакет, отмена, повтор, инвалидирование при смене входов; открытие результатов любого индекса.
7. Проверка 100/300/500 и отдельно 1000 одновременно активных маркеров в renderer. Общее N в распределённом расписании не является доказательством такой нагрузки.
8. Браузерные проверки desktop/узкого экрана, отсутствие API-записей, fallback и регрессия исходных записей.
9. Сборка, scoped lint, тесты. Записать фактические замеры; не заявлять FPS или физическую достоверность без проверки.

## Дополнение к приёмке 360°

На фиксированном seed проверены 1000 уникальных углов и присутствие во всех восьми секторах, радиусы входа/выхода, корректное положение середины и следа, границы секторов, отсутствие зависимости от library.tracks. В браузере должны отсутствовать общие А/Б/В-линии массового режима; активные 2D-маркеры и статистика секторов согласованы с расчётом, 3D использует те же координаты. Наличие всех восьми секторов в каждом коротком временном срезе не гарантируется равномерным случайным распределением.

## Дополнение к приёмке учебной защиты

Проверить охват всех четырёх участков границей; отсутствие событий до b, ровно одно событие в b, исчезновение отметки в b+60000 без удаления истории. Повторный seek и прямой переход в конец не дублируют/не теряют события; возврат к началу очищает видимую историю. 2D/3D показывают одну зону и тот же ID события; кнопка перехода к событию, счётчик, журнал и зелёная отметка согласованы. Изменение seed/параметров/индекса сбрасывает события старого прогона.
