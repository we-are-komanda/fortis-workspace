# FRC-03. Первый рабочий проект и корректный контекст предприятия

**Статус:** проект спецификации от 20 сентября 2026 года; не отметка о выполнении.
**Ответственный контур:** Frontend workspace + backend enterprise/project.
**Зависимости для приёмки:** FRC-00, FRC-01, FRC-02, FRC-04, FRC-06.
**Цель:** Новый подключённый пользователь открывает правильное предприятие и создаёт первую конфигурацию без демо-объектов и чужих вариантов.
**Архитектура:** доработка существующих модулей Fortis; границы frontend/backend/knowledge-base сохраняются. Общие определения — в `../00_SHARED_CONTRACTS.md`, типы — в `../contracts/release-contracts.ts`.
**Стек:** существующие Next.js / React / TypeScript / Zustand и Go / PostgreSQL / GORM. Версии определяются закреплённым комплектом FRC-00; обновление стека не входит в задачу.

## 1. Основание и границы достоверности

**Проверено в коде:** `filteredVariants` возвращает весь список, если scoped-список пуст. Create/open/compare уже существуют — их не нужно делать с нуля. Ошибка фильтрации сама по себе не доказывает межклиентскую утечку, но требует исправления.

Источники: [C1], [S9], [S1 раздел III]. Их статусы и ссылки собраны в `../SOURCES.md`. Требования ниже, которых нет в источниках, являются предлагаемыми решениями этого релиза, а не уже принятыми ADR.

## 2. Файлы и зоны изменения

FE: `src/modules/workspace/ui/project-workspace-page.tsx`, `src/modules/drone-defense/infra/enterprise-api.ts`, `src/modules/drone-defense/infra/api-client.ts`, `src/modules/drone-defense/domain/use-defense-variants-store.ts`.
Новые FE: `src/modules/workspace/domain/project-scope.ts`, `project-scope.test.ts`.
BE: enterprise/project list handlers и административный onboarding существующих предприятий.

Существующие пути — точки входа, а не разрешение переписать весь модуль. Предлагаемые новые пути явно названы новыми. Если FRC-00 обнаружит перенос файлов, обновить адреса в этой спеке, сохранив функциональные границы.

## 3. Входные и выходные контракты

Список проектов запрашивается с enterpriseId, limit, offset; totalItems соответствует этому фильтру и разрешениям. Нет выбранного предприятия → пустая рабочая область. Открываемый проект приносит server enterpriseId; фронтенд не меняет его из имени/центра объекта.

## 4. Требуемое поведение

1. Убрать fallback `scoped.length > 0 ? scoped : variants`. Пустое предприятие показывает «Для этого предприятия пока нет конфигураций» и create, если право есть.
2. Без enterprise membership: «Нет доступных предприятий. Обратитесь к администратору»; создание disabled. Никакого автоматического назначения demo/первого предприятия из старого кеша.
3. Для первого подключения администратор создаёт предприятие из имени, адреса и явно заданного центра, назначает участника. Координаты валидируются как GIS-данные; автоматический поиск реального объекта не требуется. Служебный процесс документируется и не требует developer SQL.
4. На смену предприятия сбрасывать выбранные сравниваемые проекты и состояние списка; не подставлять результат позднего запроса прошлого предприятия. При dirty-проекте перед уходом применяется FRC-06.
5. Создать вариант можно только в доступном предприятии. Имя после trim — 1…120 символов; пустое не заменяется названием demo-терминала. На время запроса кнопка недоступна, запрос идемпотентен по FRC-04 при подключении save.
6. Ошибка создания сохраняет ввод, не открывает `/prototype` с видимостью успеха. Успех — только после server projectId/version; затем одна операция замены current project context.
7. Реализовать loading/empty/error/forbidden раздельно, рабочую pagination, сохранение selected enterprise в user-scoped состоянии. Простая клиентская фильтрация не заменяет серверную.
8. Проекты без enterpriseId при миграции изолируются для административного разбора. Не приписывать их текущему пользователю автоматически.

## 5. Приёмка и регрессионные сценарии

| ID | Сценарий | Ожидание |
|---|---|---|
| WS-01 | Доступны E1 с 2 проектами и E2 без проектов; выбрать E2 | Ноль строк и пустое состояние; проекты E1 не показаны |
| WS-02 | Новый пользователь без назначений | Нет demo-объекта; объяснение и disabled create |
| WS-03 | Администратор назначил E2, пользователь обновил список | E2 появляется и допускает первую конфигурацию |
| WS-04 | Создание вернуло 503 | Имя сохранено, навигации в успешный проект нет |
| WS-05 | Ответ E1 пришёл после переключения в E2 | Не меняет E2 UI |
| WS-06 | 120+ проектов | Pagination/totalItems правильны, фильтр не зависит от первой страницы |
| WS-07 | Проект отсутствует или membership отозван | Понятный отказ, старый current project не подставляется |
| WS-08 | Имя состоит из пробелов | Валидация; POST не уходит |

Минимальный unit-сценарий для выделенной функции: вход `(variants=[E1:a], enterpriseId=E2)` даёт `[]`. Новый тест запускается через `pnpm exec tsx --test src/modules/workspace/domain/project-scope.test.ts`.

- [ ] После интеграции пройти релевантный сценарий на release-кандидате с реальным backend. Не использовать реальные клиентские данные для отрицательных тестов.
- [ ] Обновить матрицу приёмки и knowledge-base. После коммитов в дочерних репозиториях обновить parent pointers отдельным согласованным изменением.

## 7. Не входит в задачу

Редизайн всей рабочей зоны, новый слой «организаций» сверх существующих предприятий, CRM/onboarding wizard, автоматический импорт внешних объектов.

## 8. Что приложить к сдаче

PR или commit в каждом изменённом репозитории; перечень реализованных сценариев с PASS/FAIL; команда запуска проверок; версия окружения; миграция/откат при изменении хранения; скриншоты затронутых UI-состояний без секретов; обновлённые контракты и пункт матрицы приёмки. Нельзя закрывать задачу только по наличию кнопки, маршрута или HTTP 200.
