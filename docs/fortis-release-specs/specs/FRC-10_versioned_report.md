# FRC-10. Отчёт из одной версии: карта, состав, цены и ограничения

**Статус:** проект спецификации от 20 сентября 2026 года; не отметка о выполнении.
**Ответственный контур:** Backend report + frontend print/export + QA.
**Зависимости для приёмки:** FRC-00, FRC-04, FRC-05, FRC-06, FRC-07, FRC-09.
**Цель:** Сформировать документ, который воспроизводимо соответствует сохранённой конфигурации и не раскрывает скрываемые финансовые данные.
**Архитектура:** доработка существующих модулей Fortis; границы frontend/backend/knowledge-base сохраняются. Общие определения — в `../00_SHARED_CONTRACTS.md`, типы — в `../contracts/release-contracts.ts`.
**Стек:** существующие Next.js / React / TypeScript / Zustand и Go / PostgreSQL / GORM. Версии определяются закреплённым комплектом FRC-00; обновление стека не входит в задачу.

## 1. Основание и границы достоверности

По предыдущему аудиту печатный компонент уже есть, но в нём не подтверждены карта, переключатель скрытия стоимости и единая серверная версия. Spec 03 прямо требует report из backend payload. Нужно расширить существующий export, а не создавать красивый независимый макет с данными из store.

Источники: [S1 раздел 1.1], [S7], [S8], [S4]. Их статусы и ссылки собраны в `../SOURCES.md`. Требования ниже, которых нет в источниках, являются предлагаемыми решениями этого релиза, а не уже принятыми ADR.

## 2. Файлы и зоны изменения

FE: `src/modules/defense-calculator/ui/calculator-report.tsx`, `calculator-page.tsx`, `infra/backend-project-api.ts`, существующий print CSS и GIS renderer.
Новые: `src/modules/defense-calculator/ui/report-map-snapshot.tsx`, `domain/report-projection.test.ts`, `test/playwright/release-report.spec.ts`.
BE: existing `internal/modules/report/`, safe DTO projection, revision/cost access; при необходимости новый report artifact metadata model, без внешнего отчётного SaaS.

Существующие пути — точки входа, а не разрешение переписать весь модуль. Предлагаемые новые пути явно названы новыми. Если FRC-00 обнаружит перенос файлов, обновить адреса в этой спеке, сохранив функциональные границы.

## 3. Входные и выходные контракты

GET report принимает projectId в existing `id`, обязательную для release-клиента projectVersion и hideCost. Возвращает `ReportPayload`. Для safe unpriced варианта не допускается raw DefenseProject с embedded ценами. `mapSnapshotData` — allowlisted данные визуализации из той же revision, без стоимости/credentials/приватных ссылок. Type JsonValue не разрешает отдавать весь исходный snapshot.

## 4. Требуемое поведение

1. Official report можно получить только для существующей сохранённой ревизии с доступом. На dirty state — сохранить либо явно выбрать last-saved. Пока save не подтверждён, не открывать документ как текущий.
2. Содержимое: предприятие, имя варианта, projectId/version, дата формирования, calculationVersion, источники/quality и допущения; карта с названием и легендой; перечень позиций, количества, типа/эшелона, существующих описаний/карточек; стоимость по строкам и группам, бюджет/остаток; известные предупреждения и ограничения методики.
3. Все данные берутся из одного server payload. Renderer карты работает из изолированного frozen snapshot, а не текущего Zustand проекта. Пока строится карта, изменение рабочего проекта не меняет документ.
4. Default карта показывает все позиции отчёта. Пользовательские фильтры/скрытые слои допускаются только как явно подписанный выборочный вид; перечень позиций остаётся полным. MapVisibility включается в metadata отчёта. Нет молчаливого визуального исключения объекта из сметы.
5. Захват карты ждёт готовности слоёв/шрифтов/подложки. Ошибка загрузки карты или CORS/canvas export не даёт пустой картинки с успешным экспортом: понятная ошибка и повтор. Ни геометрия проекта, ни описание защищаемого объекта не отправляются стороннему image/export сервису. Лицензии подложки и attribution сохраняются.
6. HideCost выполняется на backend DTO projection. Исключить суммы, unit prices, бюджеты, дельты, финансовые предупреждения, embedded metadata и ссылки на прайс/коммерческие файлы. Viewer без viewCost не получает priced payload даже через прямой URL. Это не просто `display:none`.
7. У unpriced map/object data также нет embedded catalog price. Название файла отчёта не содержит суммы. Встроенные аттачменты прайс-листов не включаются. Свободные descriptions/notes могут содержать введённые человеком суммы: перед unpriced export показывается отдельное предупреждение о ручном просмотре; автоматическая очистка произвольного текста не обещается.
8. Неполные цены или demo/estimated inputs дают заметный статус «Предварительная оценка» и перечень причин. Unknown не превращается в 0. Непроверенные пространственные ограничения не подписываются «Конфликтов нет»: писать «Автоматическая проверка не выполнена».
9. Печать поддерживает повторяемые заголовки таблиц, перенос длинных названий и строк, номера страниц. Нельзя обрезать колонки и выдавать blank map. Кнопка browser print не является доказательством правильности документа.
10. Для выдачи сохраняется render-ready payload/идентичность отчёта; повторное открытие существующего reportId не подхватывает новую цену/алгоритм. PDF binary storage не обязателен для первого релиза, но исходные данные выданного документа неизменяемы и доступны по правам.
11. Пустая конфигурация формирует честный пустой документ с нулём позиций, а не каталог рекомендаций. Никаких автоматически рассчитанных вероятностей/эффективности.

## 5. Приёмка и регрессионные сценарии

| ID | Сценарий | Ожидание |
|---|---|---|
| REP-01 | Отчёт A7 из finance fixture | Все суммы 475 000 руб. / ожидаемые группы; identity A7 |
| REP-02 | Во время формирования A7 изменили draft/A8 | Документ остаётся A7 |
| REP-03 | hideCost=true | Нет финансовых полей в JSON, DOM, print HTML, PDF text и metadata |
| REP-04 | В revision есть private template price | Unpriced карта/objects не раскрывают его |
| REP-05 | Подложка/снимок карты не загрузились | Экспорт не объявлен успешным; actionable error |
| REP-06 | Длинные названия, 100 строк, несколько страниц | Нет обрезания; заголовки/нумерация читаемы |
| REP-07 | Скрыт один слой | Вид выборочный явно подписан; смета по всему проекту |
| REP-08 | Источник estimated/demo или цена null | Видимый preliminary/неполный итог, без ложной точности |
| REP-09 | Старый reportId после изменения цен | Содержимое расчёта неизменно |
| REP-10 | Ноль объектов | Пустой отчёт, total=0, не legacy/reference numbers |

Приёмка: скриншоты render и реальный PDF, с проверкой текста и визуального вида. Это работа будущего исполнителя; PDF в текущем пакете не генерировался.

## 6. Порядок реализации

- [ ] Прочитать эту спеку, общие контракты и указанные исходные файлы. Проверить чистоту рабочего дерева; не сбрасывать чужие изменения.
- [ ] Для каждого сценария раздела 5 добавить либо найти автоматическую проверку. Существующее зелёное поведение не реализовывать повторно.
- [ ] Воспроизвести ожидаемый дефект на закреплённой версии либо отметить требование как уже выполненное со ссылкой на проверку. Для нового поведения сначала получить падающий тест.
- [ ] Внести минимальное изменение в owning repository; обновить DTO/OpenAPI и миграции только там, где они затронуты этой задачей.
- [ ] Запустить профильные тесты, линтер и сборку; приложить команды, SHA и результат. Статические проверки исходного текста не заменяют behavioural-тест.
- [ ] После интеграции пройти релевантный сценарий на release-кандидате с реальным backend. Не использовать реальные клиентские данные для отрицательных тестов.
- [ ] Обновить матрицу приёмки и knowledge-base. После коммитов в дочерних репозиториях обновить parent pointers отдельным согласованным изменением.

## 7. Не входит в задачу

Создание методики расчётной эффективности, инженерная сертификация, электронная подпись, внешний сервис генерации карты, полная DOCX-редакторская система.

## 8. Что приложить к сдаче

PR или commit в каждом изменённом репозитории; перечень реализованных сценариев с PASS/FAIL; команда запуска проверок; версия окружения; миграция/откат при изменении хранения; скриншоты затронутых UI-состояний без секретов; обновлённые контракты и пункт матрицы приёмки. Нельзя закрывать задачу только по наличию кнопки, маршрута или HTTP 200.
