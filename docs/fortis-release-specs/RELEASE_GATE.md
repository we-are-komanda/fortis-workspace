# Решение о выпуске: ограниченная рабочая версия Fortis

**Исходный статус: NO-GO / не проверено.** Пакет спецификаций не изменяет статус продукта.

## Обязательные доказательства

- [ ] FRC-00: известны FE/BE commits, image/deployment и миграции; выбранный комплект воспроизводится.
- [ ] FRC-01/11: рабочее окружение без скрытых demo fallback; HTTP-ошибки имеют правильный смысл.
- [ ] FRC-02: реальная серверная изоляция, роли, цены и документы; проверены прямые API, а не только меню.
- [ ] FRC-03: новый подключённый пользователь может начать реальный проект; пустое предприятие честно пустое.
- [ ] FRC-04/06: lossless save/load, recovery и 409 без потери работы; нет silent overwrite.
- [ ] FRC-05/07: деньги точны, неизвестные цены обозначены, бюджет защищён на всех write paths и при race.
- [ ] FRC-08: сравнение фиксированных доступных revisions; корректные дельты и границы выводов.
- [ ] FRC-09: источники/quality/документы/права, проверен безопасный upload pipeline.
- [ ] FRC-10: документ со снимком карты/версией/источниками; hideCost не отдаёт цены скрытыми полями.
- [ ] FRC-12: заявки записываются; доставка уведомлений/ошибки наблюдаемы; текст обработки данных предоставлен владельцем.
- [ ] FRC-13: positive E2E с настоящим BE/БД, два desktop размера, реальные artifacts; critical tests green.
- [ ] FRC-14: восстановление выполнено, уведомления доставлены, данные/хостинг/retention согласованы, поддержка назначена.

## Классификация результата

**GO — закрытый рабочий запуск:** все пункты доказаны на одном release candidate, разрешён только согласованный круг клиентов и согласованные данные.

**GO — только демонстрация:** допускается показывать синтетические данные с явной меткой; не означает разрешение хранить клиентские данные или обещать расчётную достоверность.

**NO-GO:** хотя бы один непроверенный/проваленный critical gate. Перечислить конкретные acceptance IDs, не ставить субъективный процент готовности.

## Что фиксировать в итоговой записи

Фактическая дата/время, release manifest, результаты проверок, список принятых задач, известные несущественные ограничения, границы клиентского применения, ответственный за выпуск, ответственный за поддержку, rollback/restore evidence. До реального выполнения ни одно поле не заполнять придуманным успехом.
