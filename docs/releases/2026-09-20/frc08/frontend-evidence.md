Initial execution failed because the new implementation module was absent; the two checks then passed. This is distinguished from an existing-product regression reproduction.
- The backend integration contract test now supplies a valid pinned response and asserts all four query parameters; the existing cost/auth/route assertions were retained. The release-surface test accepts compare and keeps report gated. The cost and identity tests remained green after validator extraction and the neutral shared save-helper name.
- The coordinator observed the modal `maskClosable` deprecation in a real browser; supported `mask.closable` replaced it. The final real gate has zero console/page errors. No console filter was added.
- The coordinator/reviewer observed the historical-selection defect: current8 with A7/B8, explicit save9 yielded9/9 and disabled comparison. The fix requires matching the pre-save current version as well as ID/enterprise before repinning. The permanent historical case passes in the inspected final20 log: observed **RED → GREEN**.
- The independent initial suite's concurrent-business-edit case passed: a newer edit during PUT stays dirty, retains the dialog, and can proceed only via an explicit saved-ref choice. The strict logout save guard was not weakened for comparison.
- Owner/reviewer identified and the coordinator reproduced both known-denial races: already displayed money and a held old response survived `markProjectInaccessible(404)` for a selected operand. The fix subscribes to scoped resource denial, invalidates displayed/pending results, and checks fresh access before GET and response publication. Unrelated project denial is deliberately excluded; access is not confused with invalid version input. Both defects have observed **RED → GREEN**, and the unrelated-denial control remains GREEN in final20.
