# FRC-08 frontend implementation

Checkpoint: 2026-09-21, after accepted FRC-07 frontend `6838dd1`, backend `387572a`, parent `5008d25`. The implementation follows [ADR-0024](../../../../knowledge-base/03_Architecture/ADR-0024-pinned-saved-comparison.md) and [ADR-0017 membership authority](../../../../knowledge-base/03_Architecture/ADR-0017-enterprise-access-boundary.md). Final FRC-08 acceptance remains coordinator-owned; this document is not a whole-release acceptance.

The existing workspace comparison now selects two immutable references, each with a project and positive integer version. Selecting a project initializes its version from the current list summary, after which it stays explicit. Historical versions are entered through “Версия A” / “Версия B” and validated by the server. Both selections survive workspace pagination; a background save/list update does not silently repin them. Switching enterprise or browser identity resets the comparison state. Calculator links to the same workspace comparison instead of maintaining a second project list or model.

The [API boundary](../../../../frontend/src/modules/defense-calculator/infra/backend-project-api.ts) sends all four required parameters. It reuses the existing cost projection validator for each side, then validates the budget, tenant, pinned project/version, matching digest/calculation/input-data identity, frozen name/date, exact B−A and percentage. No legacy float comparison or conflict/coverage count is consumed. An unknown side makes both delta and percentage null; A=0 preserves the monetary difference and makes percentage null. Percentage validation uses exact integer arithmetic with two decimal places, ties away from zero, and canonical `0.00` for rounded negative zero.

[ConfigurationComparison and ComparisonResultView](../../../../frontend/src/modules/defense-calculator/ui/configuration-comparison.tsx) display frozen names, version/date, exact total and known subtotal, completeness, positions/units, real layer/type groups, budget/remainder, quantities, instance prices and provenance. Source label/date, recorded date, revision and quality are visible. Layer/type groups join on their stable IDs; detailed lines join on object ID plus asset ID. Equal names are never a match key, and unmatched entries are explicitly separate. Visible A/B labels remain clear when the columns stack on narrow screens. Differences use B−A and Russian display such as `+15,79%`; unknown or zero denominators never imply cheaper, better or measured protection.

The [comparison domain hook](../../../../frontend/src/modules/defense-calculator/domain/configuration-comparison.ts) clears prior results when references change or a request starts/fails and rejects late responses after a later selection/request or unmount. Enterprise/session keys prevent old results from becoming a new context's success. A newly known resource denial clears displayed/pending comparison only when the denied current project is a selected operand. Fresh store checks run before a request and before publishing its response; unrelated denied project C does not block A/B. Reopening an authorized resource or selecting an unrelated pair permits a new request. Access errors remain separate from numeric version validation. Server authorization applies afresh to both refs; an error never leaves a partial side visible.

Dirty comparison offers “Сохранить и сравнить”, “Сравнить последние сохранённые”, or “Отмена”. The explicit saved choice compares the selected pinned refs and excludes the local draft. Save uses the accepted common save pipeline through `saveCurrentProject`; the old `saveBeforeLogout` export remains an alias with identical strict behavior. Comparison starts only when the save is confirmed, no unresolved attempt/access error remains, and the current project is fully saved. A newer business edit during PUT keeps the dialog and draft dirty and permits an explicit saved-ref choice; the UI does not claim the acknowledged server write failed.

After an explicit successful Save-and-compare, only a selection matching the pre-save current project **and version** moves to the new confirmed ref. For selected A7/B8 of one project with current8, saving creates9 and comparison becomes A7/B9. A7 is historical and remains selected. Ordinary background saves never repin either selection.

The comparison capability now points to `/workspace#configuration-comparison`; report remains gated for FRC-10. Proposed CMP-09 viewer/viewCost RBAC is deferred under ADR-0017, while current enterprise membership and no-partial-data requirements remain mandatory. No new dependency, project model, financial projection or reservation mechanism was introduced. The new modal uses installed Ant Design 6 `mask.closable`; the initial real-run deprecation failure is retained as evidence rather than filtered.

The latest independent rendered comparison passes **20/20**, including historical repinning and both selected-resource denial races. The final real workspace → API → PostgreSQL run passes **4 checkpoints with zero console/page errors**, closing the initial modal deprecation failure. Combined browser regressions pass **76/76**, and the isolated Next.js 16.2.11 build exits0. The full suite reports **239 pass / 6 fail / 96 skip**; exact baseline-signature and final independent type/lint/hash confirmation remain pending. These results do not independently accept the whole stage or release.
